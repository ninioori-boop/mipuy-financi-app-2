# גריל — סקירה עוינת לפני פריסה

## מתי להפעיל — חובה

| מצב | להפעיל? |
|---|---|
| push ל-main של שינוי **רגיש** — לוגיקה, שמירה/טעינה, מסלולי נתונים | ✅ **חובה** |
| push ל-main של שינוי תוכן/UI פשוט (טקסט, עיצוב, סקשן סטטי) | ❌ מיותר (אורי, 05/08/2026) |
| `firebase deploy --only functions:*` | ✅ **חובה** |
| סקריפט שכותב ל-Firestore בפרודקשן (`--apply`) | ✅ **חובה** |
| שינוי ב-`firestore.rules` / `storage.rules` | ✅ **חובה** |
| שינוי בקוד שמריץ שמירה/טעינה של נתוני לקוח | ✅ **חובה** |
| commit מקומי בלבד, בלי push | ❌ מיותר |
| תיעוד, memory, קבצי תוכנית | ❌ מיותר |
| סקריפט קריאה-בלבד | ❌ מיותר |

**למה חובה:** בסשן 2026-07 הגריל רץ ארבע פעמים ומצא ממצא אמיתי **בכל פעם**. פעמיים
הוא תפס באג קריטי שקלוד עצמו יצר — כולל אחד שהיה משבית מסכים שלמים ליועץ, **בזמן
שכל הבדיקות עברו בירוק**. בדיקות ובנייה ירוקה הן לא תחליף.

## איך

הרץ סוכן `general-purpose` עם `run_in_background: false`. מבנה הפרומפט שעובד:

1. **הקשר חד:** "אפליקציה חיה, ~40 לקוחות משלמים. רק פגמים אמיתיים עם תרחיש כשל
   קונקרטי — לא הערות סגנון."
2. **נתיב מדויק** לעץ העבודה + הוראה להריץ `git -C <path> diff` ולכלול קבצים untracked.
3. **מה הכוונה של השינוי** — בפירוט. בלי זה הסוכן ממציא כוונות.
4. **רשימת ציד ממוקדת** — 5-9 שאלות ספציפיות שנגזרות מהשינוי הזה, לא כלליות.
   דוגמאות שהוכיחו את עצמן:
   - "האם הפונקציה שחולצה **זהה בייט-לבייט** למקור?"
   - "איזה caller מסתמך על ההתנהגות הישנה?"
   - "מה קורה כשהקריאה **נכשלת** — נשאר null או הופך ל-false?"
   - "האם יש מסלול שבו ה-state נתקע בערך שגוי?"
   - "האם הבדיקות בכלל מכסות את המסלול שהשתנה?"
5. **פורמט:** "דרג לפי חומרה, עם file:line ותרחיש כשל. **פרט במפורש מה בדקת ומצאת
   תקין.** אם אין ממצא אמיתי — תגיד את זה בפשטות."

## כללי ברזל אחרי שהגריל חוזר

**אל תקבל ממצא בלי לאמת בעצמך.** בסשן הזה הגריל טען שנתיב `/go/[slug]` לא קיים —
הוא חיפש בעץ הלא נכון. אימות ב-curl הראה 302 תקין. ממצא שגוי שמתקבל בעיוורון עולה
זמן ומייצר "תיקונים" מיותרים.

**ממצא שאתה מקבל — תקן לפני הפריסה, לא אחריה.**

**ממצא שאתה דוחה — תגיד למה, בפירוש**, בהודעה למשתמש. שקיפות על מה לא תוקן.

**אחרי תיקונים: הרץ מחדש בדיקות + build.** תיקון של ממצא הוא קוד חדש שאיש לא בדק.
